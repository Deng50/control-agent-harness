# 用户偏好驱动的 MPC 调参

`tune_controller` 使用已登记的预测模型和评价模型，输入为 `model`、`evaluation_model` 两个产物 ID。两者必须接口兼容。与 `synthesize_mpc` 的独立设计交付相比，本操作需要可执行评价对象及互不重叠的 tuning、verification、test 三组工况。

## 偏好配置

`config.parameters` 中的 q/r/s 是 MPC 预测时域内部权重；`config.evaluation` 是外部闭环评分。它们分别进入实际求解和候选评价，不共用一个权重字段。

```json
{
  "evaluation": {
    "recipe": "tracking",
    "scales": {"rmse": 1, "energy": 100, "tv": 10, "overshoot": 0.1},
    "hard_gates": {"constraint_tolerance": 0.000001}
  }
}
```

这个例子展示配置形式；工程评分尺度应由用户针对模型单位、运行时长和目标选择。四个尺度都必须显式为正，并在搜索前固定。支持的配方及默认权重为：

| recipe | rmse | energy | tv | overshoot |
| --- | ---: | ---: | ---: | ---: |
| tracking | 10 | 0.1 | 0.1 | 0 |
| energy | 0.1 | 10 | 0.1 | 0 |
| smoothness | 0.1 | 0.1 | 10 | 0 |

可提供 `weights` 覆盖，但必须给齐四项，非负且至少一项为正。评分为 `sum(weight * raw_metric / scale)`；硬约束或所需指标不可用的候选先排除，不用一个较低总分掩盖失效。

`energy_model` 当前只支持 `action_proxy`：每个动作通道的平方沿时间积分。它不是电功率模型或焦耳能耗；不同物理单位的通道合成值是数值坐标指标，逐通道结果保留真实单位。`tv` 是绝对动作增量之和，包括从真实初始动作到第一个动作的变化。

`hard_gates` 支持约束容差，以及 max_rmse、max_energy、max_tv、max_overshoot、max_settling_time、max_oscillation_crossings；未启用的上限为 null。`per_output` 按接口中的精确输出名称指定逐通道 RMSE、超调、调节时间和误差穿越次数上限。

## 指标口径

逐输出计算误差，并按恒定参考段切分。第一段使用动作前的实际输出作为阶跃起点，之后使用前一段参考值。方向超调为沿阶跃方向越过目标的最大幅值除以阶跃幅值；负阶跃与零目标使用同一公式，无阶跃为 null。

调节时间要求误差在容差带内持续到当前段结束，且满足最短保持样本数。没有调节成功的记录保留 null 和原因，不伪写为记录总时长或 0。振荡指标是固定死区外误差的符号变化次数，按参考段分别计算；它不是振荡频率或稳定性证明。

`evaluation.metrics` 可配置绝对/相对调节带、最短保持步数、阶跃容差及振荡死区。精确定义和每段明细写入实际报告；不存在的指标不能用于通过一个启用的硬门。

## 搜索、确认与交付

使用既有遗传算法与 MPC 数值求解器。工况只接受声明的名称、初值、参考、扰动和步数字段；按实际初值/参考/扰动判重，修改名称、时长或数字的整数/浮点写法不能形成独立条件。这是确定性重叠检查，实验覆盖度仍须按对象实际性质选择。调参工况决定候选排序，verification 决定是否接受改善；test 仅用于最终选定参数的一次评价。无改善或验证失败时保留可行基线，最终 test 失败则发布 rejected，不据 test 反选另一个参数，也不替换已有有效控制器。

报告保留 baseline、best、last、全部候选和失败原因、每个分区的实际轨迹、固定评价合同及哈希。对于支持独立导出的预测器，程序包包含选择后的预测器/控制器及调参来源报告；其他登记运行时明确报告还需要独立适配器。包构建本身没有再次运行 GA；此前真实调参的次数和评价范围在 `tuning_report.json` 中单独说明。

执行前通过 signals/training 确认模型接口、参数搜索范围、三组工况及完整评价配置。改变偏好、尺度或材料版本需要更新摘要；已确认的相同版本不反复请求确认。

当前数值评价范围是登记的可执行模型。对于 MATLAB/Simulink 数据得到的预测器，其上的闭环并不等于已经回原 `.m`/`.slx` 闭环复验；报告会分别标记。有限工况通过也不构成数学稳定性证明。
