# 从单个对象采样到预测模型

`sample_model` 得到一个受支持对象的真实模拟采样后，可用 `train_predictive_model` 训练完整的离散下一状态模型。无需再创建名义/参考双模型，也不执行用户未要求的控制器或策略阶段。只有实车表格数据时先走 `train_supervised`；数据特征宽度不能自动解释为物理状态数。

此入口要求已声明完整物理状态、控制、扰动和输出顺序及单位。训练特征固定为当前 `[x,u,d]`，目标为 `next_x`；不混入历史、隐藏记忆、参考轨迹或未来预览。派生数据接口明确标记 NPZ 数组映射和逻辑索引，不冒称 CSV 原始列。轨迹划分完全沿用原采样数据，Scaler 仍只拟合训练分区。

配置包含 `network`（数据-only 训练的实际超参数）、明确的 `C` 和可选的 `scaler`。当前物理输出适配为 `y=Cx`，会与采样的 y/next_y 校验；不默认使用单位矩阵，不把不受支持的非线性输出假装成线性输出。普通模式可从已登记模型中读取已有 C 提出建议，缺失时须解释和补充可验证映射。

NN 学的是离散 `x[k+1]`。即使原对象是连续导数函数，采样阶段已经按声明的积分方法变成下一状态；预测器不再次乘 dt，也不把状态增量或导数与下一状态相加。报告的一步预测时间为输入时刻加 dt。

报告区分：一步预测每次使用记录的真实当前状态；多步开环只使用每条轨迹的初态，后续回馈 NN 预测，沿记录的控制/扰动驱动。独立测试轨迹与源对象记录逐状态、逐输出比较；归一化尺度来自训练分区。只有预先声明了精度门限才给出是否达标，不证明未覆盖工况或真实硬件的保真度。

`learned_model` 保存物理接口、C、网络、Scaler、训练来源和一步/多步报告。其 Torch 运行时冻结网络参数，状态和控制的梯度保持连通，供后续 MPC 或可微 rollout 使用；不会伪造线性 A/B，也不把只会推理的普通 Python 包装称为可微。独立 `bundle/` 包含状态/控制/扰动/输出顺序、单位、dt，以及 `dynamics.py`、`simulate.py` 和运行说明，推理不依赖原 Plant、MATLAB 会话或原材料路径。

兼容恢复复用同一版派生数据，顶层 `resume_checkpoint` 接回共享优化器状态；不能每次重建新数据 ID 再冒充同一训练轨迹。内部数据集和中间网络不切换工作区活动模型；最终物理预测未通过时，保留此前有效的 learned 模型。

有明确名义模型及对齐数据时，仍可选择旧 `train_residual` 分支：组合为名义下一状态加状态单位的残差。状态边界、仿射平衡等约束要逐项说明；它属于物理约束残差，不等同于具有真实 ODE 残差和初始条件损失的 PINN。MPC、策略 rollout 必须实际使用组合模型，不能只展示单独残差曲线。
