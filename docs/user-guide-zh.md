# 控制工程智能体平台使用手册

本手册保留温控与八阶段的完整旧案例。V2 首次使用请先读[独立入口、当前支持矩阵与迁移说明](v2-delivery.md)；仅训练、仅设计、仅模仿均可作为任务终点，不要求沿旧案例逐阶段运行。

适用项目：`control-agent-harness`。适用环境：当前提供的 Windows PowerShell 启动方式。说明日期：2026 年 10 月 30 日。

本平台在 DeepSeek Harness 中提供对象模型自动化训练、控制算法设计与调优和控制算法轻量化三个入口。第一次使用，建议先运行随仓库提供的温控工作流，确认安装与数值计算正常；再按本手册逐阶段操作，理解模型、数据、控制器和策略如何接力。

GitHub 用于保存和管理源码。Web 服务和 Python 数值计算运行在启动脚本所在的电脑上，默认只监听本机；浏览器通过本地地址访问。

本文中的项目路径以 `D:\projects\control-agent-harness` 为例。安装到其他位置时，请替换项目根目录。新运行产生的产物 ID 必须从自己的运行结果复制，不能照搬别人工作区中的 ID。

## 主要功能与运行方式

### 三个智能体分别做什么

| 入口 | 主要输入 | 主要功能 | 主要输出 |
| --- | --- | --- | --- |
| 对象模型自动化训练 | 名义物理模型；真实状态转移数据或明确的参考仿真器 | 检查接口、导入数据、训练残差网络；可选线性最小二乘辨识 | 校正动力学、网络权重、预处理参数、适用范围与独立测试报告 |
| 控制算法设计与调优 | 已注册对象或校正模型；评价模型；目标、约束与独立工况 | MPC/NMPC 闭环仿真、遗传算法调参、独立复验；可选 KF/EKF 验证 | 可调用控制器、选定参数、依赖关系、约束和性能报告 |
| 控制算法轻量化 | 专家控制器及其评价模型；采集工况 | 专家数据采集、MLP/RNN/LSTM 模仿学习、可微物理模型上的策略优化 | 神经控制策略、标准化参数、输入输出协议及三方对比报告 |

通常的接力关系是：

```mermaid
flowchart LR
    A[对象模型自动化训练 输出校正动力学] --> B[控制算法设计与调优 输出专家控制器]
    B --> C[控制算法轻量化 输出神经策略]
    A -->|用于物理梯度微调| C
```

第三个入口不仅需要专家 MPC。做物理梯度微调时，还需要沿依赖链找到相应的可微动力学。因此，接力传递的是带接口、校验值和父依赖的完整产物，而不是单独一个权重文件。

### 表单与对话怎样选择

| 方式 | 适合的操作 | 是否需要模型 API |
| --- | --- | --- |
| 表单：选择操作、填写输入与配置、点击执行 | 明确参数的计算、重复实验、逐项检查 | 不需要；计算在本机执行 |
| 对话：描述目标，由智能体读取产物并调用工具 | 解释结果、调整配置、按明确要求组织多个步骤 | 需要可用的模型服务与凭据 |
| 串联工作流：预检并运行流程 JSON | 按配方连续完成多个阶段 | 从表单运行时不需要 |

两种入口使用同一套领域工具与产物协议。对话提交的作业也会出现在相应角色的作业列表中。对话使用所选模型服务，必要的任务上下文和工具返回内容会进入模型上下文；表单数值计算不需要向模型服务发送这些内容。

表单作业结束后，界面直接显示状态，不会自动开启一轮模型对话。需要模型解释或继续执行时，再明确提交对话请求。

### 当前支持范围

- 支持声明式离散动力学，以及通过明确积分配置接入的连续动力学。
- 支持经过检查、显式注册的独立 PyTorch 可微动力学源码。
- 对象模型可按受支持合同采数后训练下一状态 NN；只有 CSV/XLSX 数据时也可按明确列映射直接训练。原有模型校正分支采用离散下一状态残差监督学习。
- 条件热过程 PINN 使用真实方程残差、自动微分和初值项，提供有界 `T(t;T0,P)` 轨迹查询；它不提供任意状态转移接口，也不自动接入 MPC/PGAC，详见[条件 PINN](conditional-pinn.md)。
- 策略微调采用可微物理 rollout 梯度方法，不是 PPO/SAC，也没有独立学习的 Critic 网络。
- Python、MATLAB 函数、SLX 和 MDL 可进行只读材料检查。实际采数支持明确注册的 Python/MATLAB 合同，以及平坦已知模块、完整 UnitDelay 状态可读的 SLX 子集；未知模块、隐藏状态和不满足合同的工程会被拒绝。任意工程自动迁移不在已验收范围，详见[对象与采样](plant-sampling.md)。
- 纯 Python 案例不需要 MATLAB、Simulink 或 GPU。执行 MATLAB/SLX 路线需有许可的本机产品和独立配置的 MATLAB MCP/Toolkit，见[连接说明](matlab-existing-session.md)。当前训练及验收使用 CPU；安装 CUDA 版 PyTorch 不会自动启用 GPU。

## 当前电脑快速启动

如果浏览器已经能打开 [本地界面](http://127.0.0.1:5288/)，直接使用该页面即可，不要再启动第二个占用同一端口的服务。

如果服务未运行，打开 PowerShell，执行：

```powershell
Set-Location D:\projects\control-agent-harness
.\scripts\start-web.ps1
```

脚本会检查 Python 环境、Harness 构建与前端插件，并启动本机 Web 服务。正常情况下会打开浏览器；否则使用启动终端显示的带认证信息的链接进入。默认地址为 `http://127.0.0.1:5288/`。

启动后保留这个终端窗口。后续需要执行其他命令时，另开一个 PowerShell 窗口。停止服务时，在启动终端按 `Ctrl+C`。

不自动打开浏览器：

```powershell
.\scripts\start-web.ps1 -NoOpen
```

使用其他空闲端口：

```powershell
.\scripts\start-web.ps1 -Port 5290
```

更换端口后使用对应的启动链接。启动链接包含本地认证信息，不要把它放进 Git 或公开截图。

## 首次安装

### 准备环境

| 软件 | 要求与用途 |
| --- | --- |
| Windows | 当前启动脚本和实际界面验证面向 Windows；其他系统的安装过程不在本手册范围内 |
| PowerShell 7 | 提供 `pwsh`，原生工具与部分验证脚本会使用它 |
| Git | 克隆本项目和固定版本的 Harness |
| Node.js | 至少 24.9.0，运行 Harness 和 Web 服务 |
| pnpm | 使用 11 系列；固定上游的 `packageManager` 声明为 `pnpm@11.28.5` |
| Python | 项目要求至少 3.10；当前实测环境为 Python 3.10.22 |
| NumPy、SciPy、PyTorch | 由 Python 项目依赖安装，执行训练与控制计算 |

在 PowerShell 中检查命令是否可用：

```powershell
git --version
node --version
pnpm --version
python --version
pwsh --version
```

某个命令无法识别时，先完成对应软件的安装或 PATH 配置，再继续。不要为绕过安装检查而修改项目的依赖锁文件。

首次安装需要访问 GitHub、Python 包源和 pnpm 包源。Harness 的首次依赖安装与构建可能较长，应等待终端给出明确成功或错误结果。

### 克隆私有仓库

在准备存放项目的目录执行：

```powershell
git clone https://github.com/Deng50/control-agent-harness.git
Set-Location control-agent-harness
```

仓库是私有的，需要使用有访问权限的 GitHub 账号完成 Git 认证。这与后面配置的 DeepSeek API Key 是两套不同的认证。

已经有本地源码时，直接进入项目目录，不需要重复克隆到同一路径。

### 建立 Python 环境

在项目根目录执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -c constraints-v2-validated.txt -e .
```

验证依赖导入：

```powershell
.\.venv\Scripts\python.exe -c "import torch,numpy,scipy; print(torch.__version__,numpy.__version__,scipy.__version__)"
```

以下步骤都直接使用 `.venv` 的解释器，不要求先激活虚拟环境。不要从另一台电脑复制 `.venv`；请在目标机器上重新创建。

### 安装和构建 Harness

Python 环境建立后执行：

```powershell
.\scripts\setup-harness.ps1
```

脚本会依次完成：

1. 优先使用项目相邻的 `deepseek-harness` Git 源码；没有本地副本时，从官方仓库获取。
2. 检出固定提交 `f3803c96974ad4a94195fb97e5c637e9c2a3afe3`。
3. 安装 Harness 依赖，构建运行产物并执行构建检查。
4. 安装本项目的外部插件链接并构建 Web 扩展。
5. 初始化本地 Harness 配置并安装控制工程 bundle。

成功后终端会提示运行 `scripts/start-web.ps1`。仓库没有提交的 `vendor/`、`harness-plugin/lib/` 等目录会在安装过程中生成。

需要指定一个已有 Harness 源码目录时：

```powershell
.\scripts\setup-harness.ps1 -HarnessSource D:\projects\deepseek-harness
```

已经完成上游构建，仅重新安装或构建本项目插件时：

```powershell
.\scripts\setup-harness.ps1 -SkipHarnessBuild
```

`-SkipHarnessBuild` 不适合缺少 Harness 构建产物的首次安装。脚本发现已有 Harness 提交与固定版本不一致时会报错，不会替你强制重置源码。

### 创建工作目录并启动

以下命令假设已经位于项目根目录：

```powershell
.\scripts\prepare-workspace.ps1 -Prepare -Workspace "$PWD\workspaces\project-01"
.\scripts\start-web.ps1
```

工作目录用于保存这个控制项目的输入、产物和任务记录，不能填成某个单独的模型文件路径。

单独运行 `prepare-workspace.ps1 -Workspace <绝对路径>` 可只读查看物理路径、文件系统、所有者、进程完整性和有效权限。`-Prepare` 会创建需要的工作目录，且只在项目 `workspaces` 或 `test-output` 下当前用户拥有的工作区叶目录，给该用户补齐缺少的 `WRITE_DAC` 或 `WRITE_OWNER`。输出包括变更前后的实际权限。`start-web.ps1 -Workspace <绝对路径>` 可在启动前进行相同的只读检查。Web 启动后，请在网页中选择本次会话使用的工作区。

进入专业会话或提交作业时，Host 会实测作业日志使用的硬链接和文件替换，并在当前会话的沙箱内启动轻量 Python 探针。它会核验 Host 文件经 worker 替换后可回读、私有 TEMP 可清理，已有账本、计划、暂存、产物及失败归档目录保持在本工作区内。训练会在已有的输出目录额外实测写入，查看产物则只作所需的检查。失败时按返回的进程、操作、路径和系统错误码处理后重试。独立 PowerShell 入口 `run-worker.ps1 --preflight --workspace <绝对路径>` 可检查本地 CLI 进程及其 TEMP。

### 配置 DeepSeek 对话服务

只体验表单与串联工作流，可以先跳过这一步。

使用对话时，在 Harness 的设置中打开“模型”，选择或配置 DeepSeek 官方服务，填写服务商颁发的 API Key 并保存，然后在对话的模型选择器中选择可用模型。Tracking ID 不能代替 API Key。

凭据由 Harness 的本地存储管理，不要写入模型 JSON、训练配置、工作流或 Git。当前电脑已配置的凭据可以继续使用；从 GitHub 换电脑安装时，需要重新配置。

配置后可先发送一句简单中文请求确认服务可用，再进行业务对话。401 通常应先检查凭据和服务配置；它与本地 Python 训练是否能运行是不同的问题。

## 认识前端界面

进入侧栏“控制工程工作台”后，按以下顺序使用：

| 区域 | 用法 |
| --- | --- |
| 项目工作目录 | 填本次实验的绝对路径，或点击“浏览工作目录”选择 |
| 三个角色入口 | 切换对象模型自动化训练、控制算法设计与调优、控制算法轻量化；各角色保留自己的会话和表单草稿 |
| 操作 | 选择当前要执行的具体阶段 |
| 输入产物 ID / 文件路径 | 填 JSON 对象，指定模型文件、数据文件或已生成的产物 ID |
| 参数表单与阶段配置 | 设置学习率、网络、轮数或 MPC/工况参数；参数表单会同步到 JSON |
| 执行阶段 | 提交一次新的 Harness 后台作业 |
| 作业与结果 | 查看排队、运行、完成、失败状态及日志；选择需要查看的作业 |
| 阶段产物 | 查看实际产物 ID、状态和存储位置，或交给下一阶段 |
| 校验并查看报告 | 校验产物及依赖，显示保存的指标和曲线 |
| 持久任务记录与恢复 | 查看完整记录、失败重试和可用恢复入口 |

“输入产物”和“阶段配置”必须是合法 JSON 对象。路径写进 JSON 时，建议使用 `/`，例如 `D:/projects/...`。普通路径输入框可以使用 Windows 的 `\`。

不要在两个文本框中都粘贴整份请求：输入区只放 `inputs` 的内容，配置区只放 `config` 的内容。比如输入区填 `{"dataset":"实际ID"}`，而不是把 `operation`、`workspace` 等外层字段一起放进去。

浏览器保留的是表单草稿；磁盘上的工作区和产物清单才是计算结果的依据。清空浏览器存储不会删除磁盘产物，但可能丢失原来的界面草稿和会话选择。

## 第一次运行温控串联案例

这一条路径不要求你手工填写中间产物 ID，也不要求配置模型 API。

### 案例内容

案例位于 [examples/temperature-walkthrough](../examples/temperature-walkthrough/workflow.json)，模拟一个有加热器的一阶温控对象：

| 项目 | 声明 |
| --- | --- |
| 状态与输出 | 温度 `temperature`，单位 ℃，范围 10～55℃ |
| 控制 | 加热功率比例 `heater_fraction`，范围 0～1，即 0～100% |
| 扰动 | 环境温度 `ambient_temperature`，范围 15～30℃ |
| 采样周期 | 1 秒 |
| 名义模型 | `T_next = 0.9*T + 2*u + 0.1*ambient` |
| 参考仿真器 | `T_next = 0.88*T + 2.4*u + 0.12*ambient + 0.15` |

名义模型和参考仿真器有明确差异，用于演示误差学习。这里的“参考对象”是数学仿真器，不是真实实验设备。

### 创建一个新的案例工作区

在另一个 PowerShell 窗口进入项目根目录，执行：

```powershell
.\scripts\prepare-workspace.ps1 -Prepare -Workspace "$PWD\workspaces\temperature-auto-001"
```

如果这个目录已有产物或运行记录，换一个新名字，例如 `temperature-auto-002`。不要把之前的测试记录当成新运行结果。

### 在界面提交完整流程

1. 打开“控制工程工作台”。
2. 在“项目工作目录”填写刚创建的绝对路径，例如 `D:\projects\control-agent-harness\workspaces\temperature-auto-001`。
3. 进入“对象模型自动化训练”入口，展开“用户项目串联工作流”。
4. 在“流程文件路径”填写 `D:\projects\control-agent-harness\examples\temperature-walkthrough\workflow.json`。
5. 点击“检查前置条件”，等待该作业结束，确认“流程前置条件：通过”。
6. 点击“运行串联流程”，等待后台作业完成；不要反复点击提交，也不要同时向同一个工作区提交手工计算。
7. 完成后查看“流程运行”中的各阶段状态和返回的产物 ID。
8. 点击“刷新产物”，再选择模型、控制器或策略的“查看报告”。

复制流程文件的绝对路径也可以使用：

```powershell
(Resolve-Path .\examples\temperature-walkthrough\workflow.json).Path | Set-Clipboard
```

随后在“流程文件路径”输入框粘贴即可。安装路径不同时，这个命令会得到当前电脑上的正确路径。

预检只检查已知接口、文件与配置条件，不代表后续训练和优化必然成功。真正的数值计算发生在“运行串联流程”中。

### 流程会生成什么

| 阶段 | 主要产物类型 | 用途 |
| --- | --- | --- |
| nominal | `nominal_model` | 名义模型 |
| reference | `reference_model` | 明确的参考仿真器 |
| data | `transition_dataset` | 残差训练数据 |
| corrected | `corrected_model` | 名义模型加学习到的修正项 |
| controller | `controller` | MPC 控制器与独立评价 |
| expert | `expert_dataset` | MPC 闭环专家数据 |
| imitation | `imitation_policy` | 模仿学习策略 |
| optimized | `optimized_policy` | 物理梯度微调后的策略 |

正常完成会得到 8 个产物。产物的完整 ID 由本次运行生成，例如 `corrected_model-……`。不要用目录数量判断成功，应检查流程结果及各产物的 `verified` 状态。

## 手动完成温控案例

手动路径与上面的串联路径二选一开始。为了清楚观察每次交接，请单独创建工作区：

```powershell
.\scripts\prepare-workspace.ps1 -Prepare -Workspace "$PWD\workspaces\temperature-manual-001"
```

把界面的“项目工作目录”改为这个目录。以下用 `<名义模型ID>` 等占位符说明输入；执行前必须替换为当前工作区的实际产物 ID，去掉占位符两侧的尖括号。

### 检查并导入名义模型

1. 选择“对象模型自动化训练”。
2. 操作选择“检查对象材料”。
3. 输入区填写以下 JSON，配置区填写 `{}`。

```json
{
  "model_path": "D:/projects/control-agent-harness/examples/temperature-walkthrough/nominal.json"
}
```

4. 点击“执行阶段”，确认找到完整候选。
5. 点击“检查并修改模型接口”，查看温度、加热功率、环境温度的名称、单位、顺序、边界和采样周期。这个案例保持原值。
6. 确认操作已切换到“导入对象模型”，再点击“执行阶段”。
7. 记录返回的 `nominal_model-……`，后面称为 `<名义模型ID>`。

如果选择上传模型文件，可以使用“上传对象材料”选择 JSON，界面会填入 Harness 接收后的路径。检查材料本身不代表已经注册可运行模型，仍需执行导入。

这里要完整替换配置，不要保留上一轮接口确认产生的 `model_spec`，否则可能仍使用上一轮显式模型覆盖。点击执行，记录新的 `reference_model-……`。


该配置使用 `3→16→16→1` 网络、学习率 `0.008`、最多 250 轮、批量 64、早停耐心值 50。

| 内容 | 本阶段含义 |
| --- | --- |
| 三个输入 | 当前温度、加热功率、环境温度 |
| 一个输出 | 名义模型的下一状态温度修正量，单位 ℃ |

点击执行并等待完成。返回 `corrected_model-……` 后，点击“校验并查看报告”，比较独立测试分区的名义模型与校正模型 MSE。报告中的误差是模型预测误差，不能直接当成控制器的闭环跟踪误差。

1. 在已验证的校正模型下点击“交给下一阶段”。

5. 点击“采用配置并切换”，进入“控制算法设计与调优”。

接力后输入区应已填好，不需要自己寻找或复制权重文件。

### 设计 MPC 并调参

操作为“设计与调参”。保持接力得到的输入区，将配置区完整替换为 [controller.json](../examples/temperature-walkthrough/controller.json) 的内容：

```powershell
Get-Content .\examples\temperature-walkthrough\controller.json -Raw | Set-Clipboard
```

本案例的关键设置：

| 参数 | 值与含义 |
| --- | --- |
| horizon | 5 个采样步；本案例相当于预测 5 秒 |
| q | 1，跟踪误差权重 |
| r | 0.002，控制用量权重 |
| s | 0.0005，控制变化权重 |
| input_rate_bounds | 每步控制增量在 −0.35～0.35 之间 |
| parameter_space | 搜索 r 和 s，范围均为 0.00001～0.005 |
| budget | 8 次候选仿真，满足当前遗传算法至少两代的要求 |
| seed | 43 |

`input_rate_bounds` 是每个采样步的动作增量。由于本案例采样周期为 1 秒，才可以表述为每秒最多变化 35 个功率百分点；换采样周期后不能沿用这个解释。

三个工况集合各有一条独立工况：

| 用途 | 初始温度 | 目标温度 | 环境温度 | 步数 |
| --- | ---: | ---: | ---: | ---: |
| 调参 | 22℃ | 30℃ | 20℃ | 18 |
| 复验 | 24℃ | 32℃ | 21℃ | 18 |
| 最终测试 | 26℃ | 31℃ | 19℃ | 20 |

点击执行并等待 `controller-……`。再打开报告，查看候选评分、独立复验选择、测试响应曲线和约束结果。候选没有在独立复验中改善时，保留基线控制器是正常结果；不能只因为完成了遗传算法就宣称性能提升。

1. 在控制器产物下点击“交给下一阶段”。
2. 核对接力输入为选中的 `controller` 和它绑定的 `evaluation_model`。

```powershell
Get-Content .\examples\temperature-walkthrough\collection.json -Raw | Set-Clipboard
```

6. 完成后记录 `expert_dataset-……`。

本案例采集 12 个独立工况，每个 20 步，共 240 个样本。采集条件没有复用控制器保留的复验、最终测试条件。专家数据中保存实际控制动作及轨迹信息，不是凭空生成动作标签。

### 训练模仿策略

在专家数据集下点击“交给下一阶段”并采用配置，或选择“训练模仿策略”后填入：

```json

  "dataset": "<专家数据集ID>"
}
```

配置区复制 [imitation.json](../examples/temperature-walkthrough/imitation.json)：

```powershell

```

该配置为 MLP、隐藏层 `[32,16]`、学习率 `0.004`、最多 300 轮、批量 32、早停耐心值 50。

| 网络 | 输入 | 输出 |
| --- | --- | --- |
| 前面的残差网络 | 温度、加热功率、环境温度 | 温度修正量 |
| 这里的控制策略网络 | 温度、目标温度、环境温度 | 加热功率 |

两者虽然都是三维输入、一维输出，变量含义和权重用途完全不同，不能互换模型文件。

执行后得到 `imitation_policy-……`。训练可能早停，300 是最大目标轮数，不要求一定跑满。报告中的训练轮数、最佳验证表现和测试工况应以实际日志与结构化结果为准。

### 继续做物理梯度优化

在模仿策略下点击“交给下一阶段”并采用配置。系统会得到当前 `policy`，并沿其专家控制器的依赖找到对应的预测 `model`。不要把它替换成工作区中另一个同维度模型。

操作为“物理梯度优化”，配置区复制 [optimization.json](../examples/temperature-walkthrough/optimization.json)：

```json
  "epochs": 20,
  "horizon": 10,
  "learning_rate": 0.0003,
  "seed": 46
}
```

这里的 `horizon` 是可微 rollout 的训练长度，与前面 MPC 的预测步数是两个不同配置。

执行后得到 `optimized_policy-……`。打开报告，在“独立测试工况”中切换不同工况，比较专家 MPC、模仿策略和优化策略。微调可能改善，也可能没有改善，不能只凭作业完成就判断控制效果更好。

## 结果查看与判断

### 怎样找到实际输出

完成某个阶段后，查看“阶段产物”中的 ID、状态和绝对路径。也可以点击“刷新产物”，从完整清单中选择“查看报告”或“选择并接力”。

工作目录通常包含：

```text
项目工作目录/
  manifest.json          工作区产物清单及活动版本
  artifacts/            已发布产物
  failed/               失败或取消阶段及可用检查点
  .staging/             尚未发布的阶段文件
  .control-jobs/         原生任务的持久请求和事件记录
  workflows/            串联流程记录
```

校正模型通常有 `network.json`、`scalers.json`、`model.pt` 和 `report.json`。策略通常有 `network.json`、`scalers.json`、`policy.json`、`policy.pt` 和 `report.json`。具体文件以产物清单为准。

不要直接编辑已经发布的产物文件，否则哈希校验会失败。调整模型、参数或训练配置后应创建新运行。

### 状态分别是什么意思

| 状态或提示 | 含义与下一步 |
| --- | --- |
| running / Waiting for a numerical worker slot | 正在运行或等待数值计算名额；当前同一 Host 默认限制一个数值 worker |
| completed | 作业已经结束；还要检查返回的工程验证结果 |
| verified | 产物通过本次配置的检查与验收门，可以按协议用于下游 |
| rejected | 数值任务可能确实执行过，但工程验收未通过；先读失败报告 |
| stale | 某个上游活动版本已变化；不能直接把旧下游当成当前有效结果 |
| failed / killed / interrupted | 任务失败、被取消或执行被中断；查看记录和恢复条件 |
| ready | 流程预检通过，或接力所需信息已就绪；不代表训练已经执行 |
| needs_input | 接力或材料检查还需要输入；例如 MPC 工况尚未填写 |

同一工作区的冲突计算受到互斥控制，其他工作区的计算也可能排队。当前工作流运行期间，不要再向同一工作区启动另一条计算链。

### 长报告被日志窗口截断时

如果只看到大段 JSON 尾部、提示较早日志超出窗口，或对话作业没有直接显示完整图表：

1. 进入产生该作业的角色，保持相同工作目录。
2. 展开“持久任务记录与恢复”。
3. 点击“刷新任务记录”。
4. 找到对应产物的 `inspect_artifact` 已完成记录，点击“查看记录结果”。
5. 在下面查看完整结果图表；如果只选到训练完成记录，再点击产物的“校验并查看报告”。

这会读取已保存的结果，不需要重新训练。某些长报告从实时日志读取不完整时，持久记录是更合适的查看入口。

### 怎样读性能报告

- 模型 MSE/RMSE：衡量下一状态预测误差。与控制器闭环跟踪误差分别理解。
- 跟踪 RMSE：衡量整段轨迹与目标的偏差，包含起始过渡过程，不能直接等同于最终稳态误差。
- 最大约束越界：结合 `constraint_checks` 看哪些约束实际启用；没有配置的速率约束不能因为显示 0 就算验证通过。
- 控制总变差：帮助比较动作变化程度；误差下降可能伴随更积极的动作。
- 平均耗时与 p95：p95 是 95 分位耗时，不是最大耗时；本机仿真计时不等于目标硬件上的部署时延。
- 曲线或工况抽样提示：长报告可能对显示点数进行抽样，完整记录仍保存在本地文件中。

### 温控案例的已执行对照

下面是此前本机实际运行的对照，方便理解界面，不要求你的新运行得到完全相同的浮点数或耗时。

| 项目 | 已执行结果 |
| --- | --- |
| 残差训练独立测试 | 一步预测 RMSE 约从 0.209℃ 降至 0.000893℃ |
| MPC 调参 | 完成 8 个候选；独立复验保留基线 |

| 策略 | 20→28℃ 且环境18℃ | 29→31℃ 且环境19℃ |

## 使用自己的模型和数据

### 先准备这些工程信息

1. 状态、控制、输出、扰动各有哪些变量，以及明确顺序。
2. 各变量单位、合理边界、采样时间和时间语义。
3. 名义动力学及输出映射；连续对象还需积分方法与相关单位声明。
4. 实验数据的采样条件和测量渠道，或明确的参考仿真器。
5. 控制目标、动作限制、变化率限制，以及独立调参、复验、测试工况。

文件能被解析，不代表这些工程语义能够自动确定。检查结果缺少单位或信号角色时，先补充信息，不要用默认零值或相同维度代替语义核对。

### 支持的对象接入方式

| 材料 | 当前可以做什么 | 进一步执行条件 |
| --- | --- | --- |
| 声明式模型 JSON | 检查、确认接口并注册 | 符合统一矩阵/方程与接口协议 |
| 独立 PyTorch `.py` | AST检查；随后显式执行并保存源码快照 | 明确 MODEL_SPEC 或完整覆盖声明，确定性、可微、CPU float64 与规定函数接口 |
| 一般 Python 工程 | 静态材料分析 | 需整理为受支持的独立适配接口；不会自动等价迁移整个工程 |
| `.slx` / `.mdl` | 静态检查材料与部分已声明信号 | 当前没有原生 Simulink 执行适配器 |

独立 Python 模型先检查，再选择“运行并导入 Python 动力学”。这一步会执行源码，必须先检查来源与接口；静态 AST 检查本身不是安全沙箱。具体函数与连续时间约定见 [Python 动力学](python-dynamics.md)及[连续模型适配](continuous-dynamics.md)。

### 导入真实实验数据

在“对象模型自动化训练”选择“导入转移数据”。目前使用 NPZ 状态转移格式，不是任意 CSV、Excel 上传后就能直接训练。

| 数组 | 形状 | 含义 |
| --- | --- | --- |
| x | `[N,nx]` | 当前状态 |
| u | `[N,nu]` | 控制输入 |
| d | `[N,nd]` | 扰动；无扰动也应提供 `[N,0]` 数组 |
| next_x | `[N,nx]` | 下一采样时刻状态 |
| trajectory_id | `[N]` 整数 | 独立轨迹编号，至少5条独立轨迹 |

所有数值必须为有限数，不能包含 NaN 或 Inf，顺序与模型接口一致。只有输入输出测量、没有完整状态转移时，不能直接把输出数组冒充状态数组；需要先解决相应的状态重建或建模问题。

输入区示例：

```json
{
  "nominal_model": "<名义模型ID>",
  "data_path": "D:/your-project/measurements.npz"
}
```

配置区示例：

```json
{
  "source": {
    "kind": "measured",
    "description": "填写实际实验批次、传感器及采样条件"
  },
  "seed": 42
}
```

如果数据来自仿真，应使用 `reference_simulator` 来源，并提供确切的 `reference_model` 产物，不要标成 `measured`。

### 从其他工作区接力

1. 在目标工作区选择“接收外部产物”。
2. 输入 `artifact_path`，指向源工作区中包含 `artifact.json` 的产物目录。
3. 执行导入，等待文件、接口和父依赖闭包校验通过。
4. 使用导入后的产物 ID 继续接力。

```json
{
  "artifact_path": "D:/other-workspace/artifacts/corrected_model-实际ID"
}
```

配置区填 `{}`。这里不能只指向 `model.pt`，也不能直接把另一个工作区的 ID 填进当前工作区而跳过导入。详见[产物协议](artifact-protocol.md)。

### 其他独立功能

- “最小二乘线性辨识”适合满足满秩与样本条件的状态转移辨识，不是把最小二乘直接套到任意 MPC 调参上。见[线性辨识](linear-identification.md)。
- “KF / EKF 测量反馈验证”需要明确测量输出、噪声协方差、初始估计与独立工况。见[状态估计](state-estimation.md)。
- RNN/LSTM 当前输入的是明确声明的未来恒定扰动预览。需要扰动维度、预览长度及来源声明；不要按普通历史窗口网络使用。见[策略动作约束](neural-policy-action-constraints.md)。

### 从 MLP 切换到 LSTM 或 RNN

将它作为一次新训练，而不是继续加载 MLP 的检查点：

1. 选择“训练模仿策略”，输入相同专家数据集。
2. 在“网络”中选择 LSTM 或 RNN。
3. 设置“循环层数”和“每层节点数”，例如1层、32节点。
4. 设置“未来扰动预览长度”，并按实际工况选择“已知恒定扰动工况”。
5. 核对输入宽度，清除或修正从 MLP 留下的旧 `input_dim`；检查点字段留空。

当前适配的输入宽度为 `nx + ny + nd + preview_len * nd`，输出宽度为控制量数 `nu`。例如温控案例的预览长度为5时，输入宽度是 `1 + 1 + 1 + 5*1 = 8`，不能继续使用 MLP 的三维输入设置。未来扰动不满足这个已知恒定预览约定时，应使用合适的其他输入适配，而不是勾选来源后假装已获得预览信息。

## 取消重试与恢复

### 取消一个长任务

在“作业与结果”选中对应作业，点击“取消作业”，等待状态变成 `killed` 或明确失败结果。取消与进程清理需要时间，不要看到按钮已点击就马上启动同工作区的冲突任务。

已经发布的有效产物会保留。正在训练的阶段可能在 `failed/` 中保留最近完成轮次的检查点。

### 区分四种后续动作

| 动作 | 实际行为 |
| --- | --- |
| 查看记录结果 | 读保存结果，不执行训练 |
| 按原请求重试 | 按原始请求创建新作业，通常从头计算 |
| 从检查点续训 | 恢复训练状态、优化器、随机状态与已完成轮数 |
| 从已完成阶段续接 | 工作流核验后复用已完成的有效阶段，继续后续工作 |

失败作业旁的“按当前配置重试”使用当前表单，是一次新运行；它与持久记录里的原请求重试不是同一入口。

### 训练检查点续训

优先在持久任务记录中选择“从检查点续训”。手工采用检查点时，选择相同训练操作、原输入和原配置，并填写原工作区中的合法检查点。

```json
{
  "epochs": 300,
  "resume_checkpoint": "failed/imitation_policy-实际阶段ID/latest.pt"
}
```

上面的 JSON 仅说明需要增加或修改的字段，不是完整配置。其余字段必须保留原值。

`epochs` 是总目标轮数。例如在120轮中断、目标设为300，是继续到总共300轮，不是再加300轮。配置、依赖或运行时不匹配时会拒绝续训；想修改学习率、网络或早停耐心值，应作为新实验执行。

已经因早停结束的训练，不会仅因为提高总轮数就自动取消原来的早停状态。发布策略使用最佳验证权重，续训检查点则包含最近的优化器状态，两者用途不同。

### 服务被强制关闭后的检查点

如果 `.staging` 留下未发布训练文件：

1. 在相同工作区展开“强制中断后的未发布检查点”。
2. 输入日志对应的“未发布阶段 ID”。
3. 点击“校验并归档检查点”。
4. 仅当系统确认旧进程退出、检查点与依赖校验通过后，才会归档到 `failed/`。
5. 恢复原训练输入与配置，再点击“填入当前训练配置”，检查目标总轮数后提交新的训练作业。

这不是继续一个已经消失的操作系统进程。不要手工删锁或仅根据文件时间很旧就认定原任务已经结束。详细说明见[训练检查点](training-checkpoints.md)和[工作流恢复](workflows.md)。

## 常见问题

| 现象 | 排查与处理 |
| --- | --- |
| 5288页面打不开 | 检查启动终端是否仍在运行、是否用了其他端口；使用该次启动输出的认证链接 |
| 端口已占用 | 先确认已有服务；可以使用原服务，或为新实例选择不同端口 |
| Python environment is missing | 在项目根目录创建 `.venv` 并安装 Python 项目依赖 |
| Harness is not built | 首次执行完整 `setup-harness.ps1`，不是直接使用 `-SkipHarnessBuild` |
| Control Web plugin is not built | 执行安装脚本构建本项目插件；源码仓库默认不提交生成的 `lib/` |
| 找不到 `pnpm`、`node`、`pwsh` | 检查软件安装、版本与 PATH，重新打开 PowerShell 后再验证 |
| 安装下载失败 | 查看明确失败的 Git、pip 或 pnpm 步骤，确认网络与包源；不要把半完成安装当成成功 |
| 工作区 ACL 或沙箱权限错误 | 查看错误中的进程、操作、路径和系统码。用 `prepare-workspace.ps1 -Workspace <绝对路径>` 检查有效权限。若自有工作区缺少 `WRITE_DAC` 或 `WRITE_OWNER`，在项目 `workspaces/` 或 `test-output/` 下的目标叶目录显式使用 `-Prepare` 后重试。若错误指出文件占用或私有 TEMP，处理对应路径。 |
| JSON解析失败 | 检查英文双引号、逗号与括号；JSON里不要写注释，路径用 `/` 或转义反斜杠 |
| dimension、unit或sample_time不一致 | 检查接口与数据映射，修正声明或做明确的数据转换，不要补零或截断硬凑维度 |
| 找不到产物ID | 确认角色使用了正确的工作目录；外部工作区产物先导入，新运行使用自己的实际ID |
| 接力提示needs_input | 按提示补齐评价模型或工况，再采用配置执行 |
| 任务一直排队 | 查看是否有其他数值作业占用默认单worker名额；同工作区也受到互斥控制 |
| 数值作业运行较久后超时 | 当前插件默认数值超时为1800秒；检查任务规模和失败记录。确需更长任务时，应调整插件的timeoutSeconds运行配置并重启服务 |
| 401或对话无法连接模型 | 检查Harness模型服务和API Key；Tracking ID不能作为Key；先用简单对话测试 |
| 表单能计算但对话失败 | 本地算法与外部模型服务是两条依赖，先分别排查 |
| 日志只有JSON尾部、图表没出现 | 在相同角色的持久任务记录中读取对应inspect_artifact的完整结果 |
| 重启后出现unknown job | 原生job句柄可能已失效，改用持久任务记录，不要据此判断产物丢失 |
| 调参保留基线 | 候选未通过独立改善门槛；查看复验分数和约束，不能强行把候选当成更优结果 |
| 训练提前结束 | 检查早停与实际日志；最多轮数不等于必须轮数 |
| checkpoint hash或signature不符 | 检查文件是否损坏、依赖或配置是否变化；不要跳过校验直接加载 |
| output为rejected | 阅读工程验收失败原因；日志完成不代表产物可用于下游 |

如果脚本被本机执行策略拦截，先确认文件来自可信的本项目，并按当前电脑或组织的策略处理。正常启动不要求永久关闭系统安全策略或关闭 Harness 沙箱。

## 数据保存与 GitHub

| 位置 | 应怎样管理 |
| --- | --- |
| `src/`、插件源码、配置、示例、文档和测试 | 已纳入 GitHub 源码仓库 |
| `vendor/`、`node_modules/`、`.venv/`、构建输出 | 根据安装脚本重建，不复制到源码仓库 |
| `.dsh/`及凭据文件 | 本机认证、会话与设置；不提交Git |
| `workspaces/`、`test-output/` | 实验数据、模型权重、产物与任务记录；需另行备份 |
| 原始验收JSON、截图和日志 | 默认仅留本机；仓库提供脱敏摘要 |

复制工作区时应保存完整依赖和元数据，不要只备份一个 `policy.pt`。不同机器的数值运行时可能不兼容原检查点续训，恢复时以实际依赖与签名校验为准。

更新源码前先完成或停止当前长任务。可以执行 `git pull` 获取文档和代码更新；依赖或前端源码发生变化时，根据改动重新安装或构建，再重启服务。更新代码不会替你自动迁移所有旧实验的语义。

## 命令行诊断与检查

日常体验优先使用界面；以下命令用于区分安装、算法和原生集成问题。

### 查看数值worker帮助

```powershell
$env:PYTHONPATH = "$PWD\src"
.\.venv\Scripts\python.exe -m control_harness --help
```

### 单独运行内置数值演示

```powershell
.\scripts\run-worker.ps1 --demo nonlinear --workspace "$PWD\test-output\manual-nonlinear-001"
```

需要一个新的演示工作区。此命令不经过 Web 和模型对话，只能验证数值计算链，不能替代前端与原生作业验证。

### 执行项目回归

```powershell
$env:PYTHONPATH = "$PWD\src"
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
node --test harness-plugin/tests/worker.test.mjs harness-plugin/tests/job-history.test.mjs harness-plugin/tests/roles.test.mjs
```

这些检查包含实际训练、优化和文件恢复操作，耗时与机器环境有关，不是每次日常启动都必须执行。

### 执行 Harness 集成检查

这些脚本需要从 `harness-web.log` 获取当前服务的本地认证链接。若要运行它们，应在服务终端按下面方式启动并保留该终端：

```powershell
.\scripts\start-web.ps1 -NoOpen *> harness-web.log
```

在第二个终端进入项目目录后执行：

```powershell
node scripts/smoke-harness.mjs
node scripts/smoke-harness.mjs workflow-linear
node scripts/smoke-harness.mjs workflow-nonlinear
```

已配置可用模型服务时，还可执行真实对话验证：

```powershell
node scripts/smoke-model-dialogue.mjs
node scripts/smoke-business-dialogue.mjs
```

它们会创建独立测试工作区，真实对话检查会使用模型 API。原始输出记录默认不会提交 Git。`verify-business-artifacts.py` 用于复核已经完成的本地业务对话记录，不能在刚克隆、还没有该运行记录的机器上直接当作安装检查。

## 功能边界与进一步阅读

`verified` 表示产物通过本次配置的工程验收门，不表示任意工况安全、物理模型真实无误或已达到实物部署要求。新增对象需要检查测量可得性、工况覆盖、约束、计算时间和部署时的输入协议。

训练覆盖报告描述训练分区实际看到的变量范围，不能当成联合工况覆盖或外推有效性的证明。神经策略计算更快，也不自动意味着控制效果优于 MPC。
