# 直流电机：三个智能体完整网页演示

## 开始之前准备什么

本演示是教学数学仿真。准备名义模型 nominal.json、参考对象 reference.json，以及 physical-parameters.json 的物理参数说明。实际实验若没有参考仿真器，模型校正应改为导入有来源的实测转移数据，不能把名义模型自身生成的数据当作实际对象误差。

电机方程：

`L di/dt = U - R i - Ke ω`

`J dω/dt = Kt i - b ω - τL`

|参数|名义模型|参考对象|单位|
|---|---:|---:|---|
|电阻 R|2.0|2.3|Ω|
|电感 L|0.5|0.55|H|
|转动惯量 J|0.020|0.024|kg·m²|
|黏性摩擦 b|0.020|0.024|N·m·s/rad|
|反电势系数 Ke|0.100|0.105|V·s/rad|
|转矩系数 Kt|0.100|0.095|N·m/A|

这些是本案例选定的示例参数，不是某一实际产品的辨识结果。

进入项目目录后，通过 scripts/start-web.ps1 启动本地前端。首次运行需要完成环境安装与 Harness 构建，通用说明见 docs/user-guide-zh.md。本次实际演示已经启动本地 5288 端口服务。

网页中点击侧栏“控制工程工作台”，填写工作目录：

`D:/projects/control-agent-harness/workspaces/dc-motor-web-20261109`

本次数字作业由网页表单提交到 Harness 后台计算；表单执行无需模型自动推断未声明的物理意义。对话辅助功能另外需要有效模型服务。截图不含凭据。

## 第一阶段：模型校正

### 1. 检查名义模型

点击“对象模型自动化训练”，操作下拉框选“检查对象材料”。在“输入产物”中填写：

```json
{"model_path":"D:/projects/control-agent-harness/examples/dc-motor/nominal.json"}
```

“阶段配置”为 `{}`，点击“执行阶段”。看到“有完整候选，待确认”后，点击“检查并修改模型接口”。

### 2. 确认接口

|需要用户确认|本案例取值|为什么要确认|
|---|---|---|
|状态顺序|电流 i 在前、转速 ω 在后|矩阵、训练数据与网络输入必须同序|
|状态单位|A、rad/s|rpm 必须先转换；更改单位名称不会自动转换数据|
|输入与输出|输入电枢电压 U，输出转速 ω|输入不是目标转速；目标是控制器的参考信号|
|扰动|负载转矩 τL，正方向为阻碍正转|进入机械方程的符号为负号|
|采样周期|0.1 s|连续方程使用精确 ZOH 转换为离散预测|
|状态边界|电流 ±12 A、转速 ±40 rad/s|后续控制器与轻量策略继承同一接口|
|控制及扰动边界|电压 ±24 V、负载 ±0.1 N·m|本演示允许双向电压与正负负载|
|观测假设|完整状态与负载均可得|本案例没有估计器；实物需考虑测量或估计|
|物理方程及参数|检查模型矩阵及 physical-parameters.json|静态检查不证明物理参数真实性|

核对后，操作已变为“导入对象模型”，点击“执行阶段”。本次名义模型 ID 为 `nominal_model-8d8e2c4ff565`。

### 3. 导入参考对象

操作仍为“导入对象模型”。将输入完整替换为 reference.json 路径，阶段配置完整替换为：

```json
{"source":{"kind":"reference_simulator","description":"Explicit DC motor mathematical reference simulator; parameter mismatch; not measured data"}}
```

点击“执行阶段”，本次参考对象 ID 为 `reference_model-4787f33a0d3d`。必须清除之前接口确认生成的 model_spec，防止误用旧方程。

本次第一次使用中文 source.description 时后台出现 UnicodeEncodeError，随后在网页中改用以上英文说明重试成功。中文物理说明仍在案例文件中；失败记录保留。

### 4. 采集转移数据

操作选“生成指定仿真数据”。输入名义模型与参考模型 ID：

```json
{"nominal_model":"nominal_model-8d8e2c4ff565","reference_model":"reference_model-4787f33a0d3d"}
```

阶段配置粘贴 data.json 全部内容。确认 30 条轨迹、每条 40 步、种子 241，点击执行。本次得到 `transition_dataset-fc1902d7abcb`，共 1200 条样本。按完整轨迹分为 720/240/240，不随机拆分相邻时刻。

若改用实测数据，需要至少 x、u、d、next_x、trajectory_id，数组列顺序与模型一致，各行对应同一采样周期；至少五条独立轨迹。还需明确测量来源、单位、时序对齐及噪声处理。

### 5. 训练残差网络并接力

点击数据产物“交给下一阶段”，等待出现“已校验的阶段接力”，点击“采用配置并切换”。网页自动填入名义模型与数据 ID，操作切换为“训练残差网络”。

阶段配置粘贴 residual.json。确认输入 `[i,ω,U,τL]` 4维、输出下一状态残差 `[Δi,Δω]` 2维，隐藏层24/24、学习率0.005、最多300轮、批量64、早停耐心50。检查点留空，点击执行。

本次校正模型 ID 为 `corrected_model-2316074cee01`。点击“校验并查看报告”查看训练曲线、测试结果、生成文件与适用范围。模型权重 model.pt、结构 network.json、归一化 scalers.json 和报告一起保存。此处学习离散下一状态误差，不宣称完整 ODE 方程残差 PINN。

## 第二阶段：MPC 设计与遗传调参

在校正模型产物点击“交给下一阶段”。此时提示“待设置工况”是正常输入提醒。点击“采用配置并切换”，进入“控制算法设计与调优”，操作“设计与调参”。输入自动绑定本次校正模型和参考对象。

粘贴 controller.json 完整内容，执行前确认：

|确认项|本案例|
|---|---|
|预测模型|校正模型，而非名义模型或参考对象|
|评价对象|独立参考仿真模型|
|预测窗口|6步 × 0.1 s = 0.6 s|
|初始权重|q=1，r=0.15，s=0.04；按接口范围归一化|
|搜索变量|仅 r∈[0.0005,0.2]、s∈[0.0001,0.08]|
|搜索预算|12个GA候选，种子243|
|硬约束|继承电流、转速、电压边界|
|电压变化|s为软惩罚，没有额外变化率硬约束|

|工况用途|初始 [i,ω]|目标 rad/s|负载 N·m|步数|
|---|---|---:|---:|---:|
|调参|[0,-5]|14|0.04|30|
|独立复验|[1,6]|-12|-0.05|30|
|保留测试|[-1,-3]|16|0.06|30|

点击“执行阶段”，观察 controller_tuning 候选进度。完成候选后还要复验与测试，不能在12个候选刚结束时就声称作业完成。候选必须通过独立复验才采用，否则保留初始参数。点击产物“校验并查看报告”，查看初始/调参对比、选定参数、约束及测试轨迹。

输出为 controller 产物：controller.json 保存预测模型和评价对象ID、求解器与选定参数；report.json 保存候选、复验、测试。它是优化控制器定义及依赖，不是控制神经网络权重。

本次已发布控制器 ID：`controller-38a2208fdab5`，独立复验接受候选，选定 r=0.0012380377987372404、s=0.029371801445906166。

## 第三阶段：控制器轻量化

### 1. 采集专家数据

在 controller 产物上点击“交给下一阶段”→“采用配置并切换”。进入“控制算法轻量化”的“采集专家数据”。输入为本次 controller 与 reference_model ID。

粘贴 expert.json，确认12个正负目标、不同初始电流/转速和负载工况，各30步。确认专家数据的生成控制器确为第二阶段选定版本。点击执行，输出 expert_dataset；应检查实际样本数、完整工况划分、控制动作与约束。

### 2. 模仿学习

本次专家采集曾在6/12个工况后达到后台30分钟时限，未发布完整数据集。恢复网页后按原配置重试；不改变已有校正模型或MPC。失败记录和重试记录都保留在原工作空间与素材执行记录中。

在专家数据产物上点击“交给下一阶段”→“采用配置并切换”，进入“训练模仿策略”。粘贴 imitation.json。

确认网络输入 `[i,ω,目标转速,τL]` 4维，输出电压1维；本例 MLP 隐藏层64/48、学习率0.002、最多600轮、批量64、耐心100。按工况拆分训练/验证/测试，测试不用于训练或选择最佳权重。早停及最佳检查点的轮数以报告为准。

点击执行后输出 imitation_policy，包含 policy.pt、network.json、scalers.json、policy.json、训练报告及恢复检查点。

### 3. 物理策略优化

在模仿策略产物上点击“交给下一阶段”→“采用配置并切换”，进入“物理梯度优化”。核对 policy 是本次模仿策略，model 是与专家 MPC 同版本的校正模型。

粘贴 optimize.json，确认40轮、rollout6步、学习率0.0003、批量24、模仿保持权重0.1、约束惩罚100。点击执行，输出 optimized_policy。查看两个留出工况上的专家/模仿/优化曲线、精度、控制耗时和约束。

这里采用可微物理 rollout 的策略梯度，无学习型 Critic。不得将“成功执行”理解为“必然改善”；即使部分工况变差，也保存原始结果。秒转毫秒必须乘1000，平均调用耗时不是端到端实时性证明。

## 保存位置与演示建议

原始权重、数据与报告在工作空间 artifacts/；网页作业记录在 .control-jobs/；截图在 presentation/screenshots/；完整中文曲线 PNG/SVG/PDF 和原始 CSV 在 presentation/figures/、source-data/；指标在 metrics-summary.json。使用案例结果与演示说明.md 的实际数字制作PPT。

建议讲解顺序：电机方程与参数失配 → 接口确认 → 独立预测校正 → 模型产物接力 → MPC约束与三组工况 → 遗传调参复验 → 专家数据接力 → 模仿与物理优化 → 相同留出工况的精度/耗时权衡。

## 如何重新加载训练好的网络

在项目根目录的 PowerShell 中运行：

```powershell
$env:PYTHONPATH="$PWD\src"
.\.venv\Scripts\python.exe -B examples/dc-motor/load_trained_policy.py workspaces/dc-motor-web-20261109 --current 0 --speed 0 --target 12 --load 0.02
```

这只读取已发布网络并计算一次动作，不会重新训练。本次上述输入输出24 V，符合电压上界。整网应通过 load_policy 加载，以同时恢复结构、归一化、输入顺序和控制约束。

素材包中的 trained-artifacts/ 是已验证的可加载八产物快照；也可把它的绝对路径作为此脚本的 workspace 参数。快照 manifest 仅调整相对存储路径，产物ID及其哈希不变，仍需本项目Python运行环境。

## 如何重跑新的独立实验

沿本文逐阶段执行时，使用新的工作目录，记录新生成的产物ID。也提供 workflow.json 八阶段配方，供“用户项目串联工作流”先预检再运行；该文件是本次配置的复现配方，本次实际执行走的是网页逐阶段表单。

结束后可在项目目录执行（将路径换为新实验目录）：

```powershell
$env:PYTHONPATH="$PWD\src"
.\.venv\Scripts\python.exe -B scripts/export_dc_motor.py workspaces/dc-motor-web-20261109
.\.venv\Scripts\python.exe -B scripts/audit_dc_motor_figures.py workspaces/dc-motor-web-20261109
.\.venv\Scripts\python.exe -B scripts/package_dc_motor.py workspaces/dc-motor-web-20261109
```

这些导出脚本不重新训练或调参；只读取已发布权重，额外计算固定恒压模型预测，导出曲线并打包。绘图审计使用本机 nature-figure 工具路径。后台真实作业与所有失败尝试见网页阶段执行记录.json 和 execution-records/。
