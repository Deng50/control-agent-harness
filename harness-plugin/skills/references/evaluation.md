# 评价与交付

比较必须使用同一对象版本、初值、参考、扰动、dt、时长、约束与指标定义。预测同时关注独立单步和多步误差；有物理模型时对比，无模型则标记不适用，不编造基线。

MPC内部Q/R/S与外部评分权重分开。外部评分尺度严格为正且在搜索前固定，先过滤硬约束失败候选，再比较归一化误差、能耗或动作代理、平滑度和超调。实际能耗需要功率模型；动作平方只是代理。偏好改变要进入计算，所有候选中同一最优方案仍领先也可能合理。

逐输出报告误差与单位。超调按阶跃方向和幅值定义，零/负目标及无阶跃分别处理；调节时间规定误差带及保持窗口。有限闭环未发散不能称数学稳定性证明。失败、无改善、未实例化、未闭环和不适用均如实展示。

轻量化比较expert/imitation/optimized，保留最佳可行基线。推理计时固定硬件、线程、批量与热身，分开控制器和对象仿真耗时。可微改写要有数值与梯度对照，策略优化后回原对象复验；代理梯度不冒充真实物理梯度。

报告指标和曲线回读实际结果文件。交付模型/控制器/策略、依赖及来源、预处理、接口/记忆、实际配置和推理样例；权重文件存在不等于能独立使用。

在线训练前冻结原对象验证/盲测工况和 `original_evaluation.evaluation` 中的最小相对改善、最差工况容许退化。每次比较让 MPC、模仿、候选各自维护状态与上一实际动作，复用相同初态、时序和噪声。按族列出闭环 J、跟踪 RMSE、动作变化、越界次数及峰值。列出专家调用、学生对象步数和更新次数后再比较不同训练方法。说明第 0 轮、最后一轮、验证选中的版本、盲测结果及实际交付权重。可行基线回退单独记作回退。

专家成本至少分列有效控制决策、专家源函数实际执行、学生仿真步数和梯度更新次数。读取采集/验收报告的 `valid_rows` 及 `expert.source_invocations_this_adapter`。后者按适配器实例累计；若跨阶段复用实例，按计数增量统计。成功的 Python 专家决策会重复原模块执行并核对新模块，三次源执行对应一步。重试或续跑时同时标记未观测的历史调用。性能测量按每个配对分别计入原始专家的上下文预检、预热及计时调用。能直接区分“专家函数执行、解析解、约束求解器调用”时各自上报；缺少分支计数时保留这个限制。
